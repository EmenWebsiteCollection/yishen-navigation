# 项目定位

一个由多个用户共同维护的网站导航平台。

所有访客均可浏览网站；登录用户可以提交网站；管理员负责账号管理、用户管理及网站内容管理。

本项目采用持续迭代开发方式，不追求一次性完成所有功能，而是在开发、测试、修改和完善中不断更新。

---

# 项目目标

建立一个简洁、稳定、易维护的网站导航平台。

用户登录后可以提交优质网站，为网站填写标题，并共享给所有访客浏览。

---

# 用户角色

## 游客（Guest）

权限：

- 浏览首页
- 浏览网站详情页
- 跳转至原网站

限制：

- 无法登录后台
- 无法上传网站
- 无法编辑网站

---

## 普通用户（User）

权限：

- 登录账号
- 上传网站
- 编辑自己上传的网站
- 删除自己上传的网站

限制：

- 无法创建账号
- 无法编辑他人的网站
- 无法管理用户

---

## 管理员（Admin）

权限：

- 创建账号
- 修改用户密码
- 删除用户
- 封禁用户
- 编辑所有网站
- 删除所有网站

管理员拥有最高权限。

---

# 账号系统

账号由管理员创建。

登录方式：

- 用户名
- 密码

系统特点：

- 不开放注册
- 不绑定邮箱
- 不绑定手机号
- 不需要验证码
- 不提供找回密码功能
- 密码由管理员修改

# 网站数据

目前每个网站包含以下信息：

- 网站 URL
- 网站标题

后续新增字段时，再更新 Project.md。

---

# URL 规则

每个 URL 在系统中只能存在一次。

例如：

https://github.com

若再次提交相同网址，系统提示：

> 该网址已存在，无法重复创建。

---

# 标题规则

一个 URL 对应一个标题。

两者保持一一对应关系。

上传完成后：

- 普通用户可编辑自己上传的网站标题。
- 管理员可编辑所有网站标题。

---

# 删除规则

删除网站后：

- 数据永久删除。
- 相同 URL 可以重新上传。

---

# 网站展示

首页展示：

- 网站标题

点击标题后：

进入网站详情页。

在详情页中可进入原网站。

# 项目规模

预计用户数量：

几十人。

项目优先考虑：

- 简洁
- 易维护
- 易扩展

不以高并发作为目标。

---

# 设计原则

1. 一个 URL 对应一个标题。
2. 一个 URL 在数据库中只能存在一次。
3. 游客可浏览，不可编辑。
4. 普通用户仅管理自己的内容。
5. 管理员负责账号及全站管理。
6. 保持界面简洁，避免功能冗余。
7. 每新增需求，应先更新 Project.md，再进入开发。
