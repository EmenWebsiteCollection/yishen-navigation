# 想法集中营 · 运营手册（docs/ideas-ops.md）

> 目标：让「想法集中营」不变成坟场。Fider 的教训——板子凉不是因为没人关心，而是没人回应。
> 核心原则：**每条想法都有状态，每个状态都有一句理由，被实现必须回链。**

## 1. 上线即种子（防「空冰箱」陷阱）

- 迁移 `20260808_add_idea_camp.sql` + 种子 `supabase/seed/idea_seed.sql` 已执行。
- 种子包含 13 条真实想法：3 条「已实现」示范（搜索 #19 / 演示视频 #10 / 图片优化 #14）+ 2 条置顶运营位 + 8 条灵感。
- 规则：**上线前不许出现零想法状态**；后续清库重开时，先跑种子再放入口。

## 2. 每周 30 分钟例行（建议固定时间，如每周一上午）

1. 新想法回状态：本周新增的每条想法至少标一个状态（含一句理由），完成「反馈闭环」。
2. 合并重复：发现重复想法 → 在目标想法页用管理员「合并」把票数/评论并入，源想法自动关闭。
3. 清陈旧：超过 4 周无人投票且已过时/无法实现的想法 → 标「已关闭」+ 一句理由（拒绝也要给理由）。
4. 置顶本周主题：发布一条 `pinned` 主题帖（见下）。
5. 看板（可选）：本周新增 / 高票未回应 / 待合并清单。

## 3. 「想法星期三」周主题（稳定内容供给）

- 每周三由管理员发布一条置顶想法，例如：
  - 「最想被做成网站的 App 点子」
  - 「给首页加一个你需要的功能」
  - 「如果你是产品经理，第一个砍掉什么」
- 周五汇总：票数最高的 3 条转成 GitHub Issue，进开发队列；结果写回想法状态（done/closed + 理由）。

## 4. 闭环仪式（最重要的信任资产）

- 任何想法被实现：作者/管理员在想法详情页「关联作品」或经「去实现」新建作品 → 状态自动变「已实现」并回链作品。
- 作品详情页会显示「孵化自想法：xxx」；首页更新记录（Changelog）同步可见。
- 被实现的想法作者会看到「✓ 已实现」高亮——这是让用户继续提想法的核心激励。

## 5. 防刷与治理

- 一人一票（数据库唯一约束）；匿名账号禁止发布/投票/评论（RLS）。
- 发布限流：1 小时 ≤3 条、24 小时 ≤10 条（服务端校验）。
- 合并/删除仅管理员或作者本人；评论删除仅本人或管理员。
- 发现刷票/水军：直接删除相关投票并关闭想法，必要时拉黑账号（管理员可在 Supabase 中操作）。

## 6. 状态语义（写入代码与文案）

| 状态 | 含义 | 何时进入 |
| --- | --- | --- |
| 灵感 idea | 刚发布，待回应 | 默认 |
| 开发中 developing | 有人在做/立项 | 作者或管理员改 |
| 已实现 done | 已有对应作品 | 关联公开作品后自动 |
| 已关闭 closed | 拒绝/搁置/已合并 | 必须带一句理由 |

## 7. 常用 SQL 速查（管理员在 Supabase SQL Editor 用）

```sql
-- 本周新想法
select title, created_at from public.ideas where created_at >= now() - interval '7 days';
-- 高票未回应（票数≥3 且状态还是 idea）
select i.title, i.vote_count from public.ideas_with_stats i
where i.status = 'idea' and i.vote_count >= 3 order by i.vote_count desc;
-- 待合并：标题高度相似（按关键词人工判断）
select id, title from public.ideas order by lower(title);
```
