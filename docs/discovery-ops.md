# 作品发现 + 反馈系统 · 运营手册（Issue #39）

> 功能组运营参考：系统上线后的「内容与闭环」日常维护。核心原则——
> **每条想法/作品都要有回应；拒绝也要给理由；被采纳要给荣誉。**

## 1. 上线即种子（避免空板劝退）

- 用真实作品给各 rail 造数据：
  - `编辑精选`：选 3 件有代表性作品（管理员在详情页点「☆ 设为编辑精选」）。
  - `零评论`：保留 3-5 件零评论作品作为「救场位」，不要一次全评完。
  - `小众宝藏 / 正在成长`：优先给标签/风格/工具填写完整的作品补齐信息（这些是相似推荐与灵感地图的数据源）。
- 给 3-5 位活跃创作者互相关注（关注动态 rail 需要 follows 数据）。

## 2. 每周 30 分钟例行（CheckList）

- [ ] ① 编辑精选换新：`set_featured` 更新 1-3 件，并同步到「更新记录」页周报。
- [ ] ② 零评论救场：给本周新作品写 1 条「单纯欣赏」或「具体建议」评论（首次评论会点亮该作品）。
- [ ] ③ 检查相似/重复作品：合并或标注（灵感地图可辅助发现同主题作品）。
- [ ] ④ 二创/版权举报处理：按「通知-删除」流程，下架违规并记录。
- [ ] ⑤ 清理陈旧：过时作品标 `status='abandoned'` 或私密，不删除用户内容。

## 3. 「今日随机」运营

- 随机推荐语由系统自动生成（含 rail 来源）；每周在更新记录里回顾「上周被随机到的宝藏作品」，鼓励作者认领。
- 若随机池过小（作品少），降低质量门槛前先补精选。

## 4. 采纳仪式（反馈闭环的关键）

- 鼓励创作者标记「采纳这条建议」并写一句采纳说明 → 自动写入作品成长档案 + 评论者信誉分。
- 每月在首页/更新记录晒「本月最有价值建议」与「本月被采纳最多的评论者」。
- 目标：每条高质量建议都有结果（被采纳 / 被作者回应 / 被标记暂缓），避免「发完石沉大海」。

## 5. 数据看板（MVP+，可选）

- 管理员页面显示：本周新作品数 / 零评论作品数 / 被采纳建议数 / 编辑精选待选池。
- 当前可直接用 SQL 查询：
  ```sql
  select count(*) from works where visibility='public'
    and created_at >= now() - interval '7 days';            -- 本周新作品
  select count(*) from works_discovery where comment_count = 0; -- 零评论
  select count(*) from comments where adopted;                -- 被采纳建议
  ```

## 6. 合规与安全提醒

- AI 参与程度为必填：未知时详情页自动加注风险提示；引导创作者在文件元数据加隐式标识。
- 批注/评论均为纯文本渲染，禁止富文本；发现异常内容走管理员删除。
- 评论质量评价一人一票一类型，匿名禁投；不做公开排行榜，防止刷评审。
